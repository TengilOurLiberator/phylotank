# Packaging: design notes (phase 1)

Owner: packaging. Scope: `packaging/**`, `.github/workflows/**`, `docs/INSTALL.md`. Nothing here is part of the sim; the wrappers open pages served by the host or the bundled standalone views.

## Decisions

1. **Lively loader at top level, tank in an iframe.** `index.html` and `loader.js` stay at top level so Lively's script calls reach them (05 §5.6.1). The host page goes in an iframe when the host answers, otherwise the zip's own dream tank (DESIGN R31). The loader keeps probing (1, 2, 4, 8 s, then 10 s), swaps to the host when it appears, and back after 3 missed checks in a row. The state machine is pure (`PhylotankLoader.step`) and unit-tested.
2. **Worker shim for `file://`.** Chromium refuses `new Worker('sim-worker.js')` from a `file://` page (measured, `docs/spikes/packaging-4.md`). The zip's `tank/wallpaper.html` is `dist/wallpaper.html` with `sim-worker-inline.js` and `worker-shim.js` before `app.js`, and `blob:` added to `worker-src`. The patch fails the build loudly if the page's shape changes.
3. **No zip dependency.** `packaging/shared/zip.mjs` writes and reads plain zips with `node:zlib` (fixed timestamps, so builds are reproducible). The Lively thumbnail is drawn procedurally, so the repo has no binary assets.
4. **One Cargo workspace for the native parts** (`packaging/Cargo.toml`): `common` (probe, restart policy, `host.json`, static file resolver, command-line quoting, Win32 helpers), `screensaver` (`phylotank.scr`) and `tray` (`Phylotank.exe`). Windows code sits behind `cfg(windows)`, so `cargo test` runs the shared logic on Linux and `cargo clippy --target x86_64-pc-windows-gnu` checks the rest from Linux.
5. **Screensaver.** wry 0.57 plus tao 0.37 (WebView2). Sources in order: the host's `screensaver.html`, the bundled standalone views through the `phylotank` custom protocol (a real origin, so the worker loads), and an inline idle animation, so it is never black (R25). If the host is down it starts the tray with `--background` and switches to the host page if the host answers within 10 s. Exit: Raw Input with `RIDEV_INPUTSINK` on the first window (replacing tao's own registration), decided by `ExitGate` (key, button or wheel down exits; releases never do; moves only after 500 ms and beyond 8 px from the start position); page listeners posting `exit` over wry IPC as a second path; `WM_ACTIVATEAPP(false)` after the grace period, `WM_DISPLAYCHANGE` and close. The window procedure is subclassed through `GWLP_WNDPROC` (no comctl32 dependency). Preview (`/p`) is a GDI child window (dark gradient and drifting motes at 15 fps) that exits when its parent dies. Configure (`/c`) is a message box that opens the god window.
6. **Tray: a light tao plus tray-icon shell, not full Tauri v2.** Reasons: v0.1 to v0.4 need only a tray menu, a supervisor and a Run key, which this does in a few hundred lines; it shares tao and the `common` crate with the screensaver; it needs no `tauri.conf.json`, icons, frontend bundle, IPC capability files or bundler, all of which v0.1 does not ship (R20: portable zip, no installer); it type-checks from Linux. The god window opens in the default browser. **When to move to Tauri:** v0.5, when the god window needs native file dialogs and notifications through a narrow IPC capability (05 §5.6.4), or v1.0, for its NSIS per-user bundler. The supervisor (`tray/src/supervisor.rs`) is framework-free and moves across unchanged.
7. **Supervisor.** Spawns `node host.mjs --port P --static <dir>` with `BELOW_NORMAL_PRIORITY_CLASS | CREATE_NO_WINDOW`, logs to `%LOCALAPPDATA%\Phylotank\logs\host.log` (one rotation at 5 MB), writes `host.json` atomically, polls `/health` every 5 s, restarts after an exit or 3 missed checks with 1, 5, 30, 120 s backoff, and gives up after 5 crashes in 10 minutes until "Restart host". It picks the next free port when 47615 is taken. Single instance: the named mutex `Local\Phylotank`; a second launch opens the running one's god window.
8. **Autostart off by default.** R20 says no autostart key in v0.1, while this phase's brief asks for the HKCU Run key: the tray has a "Start with Windows" checkbox and `install.ps1 -Autostart`, both opt-in. The value is `"<path>\Phylotank.exe" --tray`, which waits 20 s after logon.
9. **Install without admin.** `install.ps1` copies to `%LOCALAPPDATA%\Programs\Phylotank`, removes the Mark of the Web from its own files, sets `HKCU\Control Panel\Desktop\SCRNSAVE.EXE` (8.3 short path when there is one), remembers the previous screensaver for `uninstall.ps1`, and adds a Start menu shortcut. A test checks the scripts never touch HKLM, System32 or Program Files. The optional elevated copy to System32 (05 §5.6.2) is documented as a manual fallback, not scripted.
10. **CI.** `ci.yml`: Ubuntu `web` (npm test, build, Playwright e2e, Lively zip and its `file://` check), Ubuntu `native-check` (fmt, clippy, cargo test including the supervisor against the real host, clippy for the Windows target), and `windows` (cargo test and release build, portable zip with the runner's `node.exe`, then install, `/p 0`, tray-brings-up-host and uninstall as a normal user under Windows PowerShell 5.1). `release.yml` on `v*` tags makes a **draft** prerelease with the three zips and `SHA256SUMS.txt`, because the binaries are unsigned (R20).

## Not done, or later

- The `/p` preview does not yet draw the host's `/thumbnail.png` (05 §5.6.2); the host has no such route.
- Screensaver audio setting, EcoQoS for the host process, `WM_QUERYENDSESSION` handling with `ShutdownBlockReasonCreate`, OS probes (fullscreen, NVML, battery): v0.2 and later, with the host's throttle states.
- LAN binding, pairing and the Android TV app (v0.6; notes in `packaging/android-tv/README.md`).
- Code signing, NSIS installer, npm package and the GitHub Pages demo (v1.0).
- PowerShell scripts were not run here (no PowerShell in the container); the Windows CI job runs them.
