# 07. Creature designer, god-mode window and UX

Status: draft for William's review, 2026-11-04. Scope: everything a person sees or touches. That covers the creature designer, the species library and sharing, the god-mode window, the caption-only views (screensaver, TV), the no-UI wallpaper, onboarding, accessibility, input, localisation and species naming.

Other sections were being written in parallel, so this one depends on them only through the small interfaces in section 0. If the genome, sim or architecture sections pick different internals, only the adapters in 0.2 change.

---

## 0. Ground rules and interfaces

### 0.1 UX principles

1. **One world, many windows.** The sim host owns the world. Every view, the god window included, is a client. Every UI action that changes the world is a typed command to the host, so it is logged, broadcast and replayable. No view keeps world state of its own beyond render interpolation.
2. **Chrome lives only in the god window.** The wallpaper has none. The screensaver and TV get at most a caption line and, on TV, a summonable overlay.
3. **Never block the tank.** No modal dialog pauses the sim unless William asks it to. Dialogs float over a live viewport.
4. **Honest numbers.** The designer shows predictions labelled as estimates, measured values from a real physics test tank, and live values from the world. It never mixes them up.
5. **Warn, never forbid.** Inviable designs, absurd knob settings and world-ending powers are allowed. They are flagged, auto-snapshotted where destructive, and undoable through rewind.
6. **Calm by default.** Motion in the UI is short (at most 150 ms), uses no bounce and does not flash. Nothing in the UI competes with the glow of the creatures.

### 0.2 Interfaces assumed from other sections

The UI needs exactly these things from the rest of the system. Names are TypeScript.

### 0.3 Process and page layout

| Route | Who opens it | UI | Input | Notes |
|---|---|---|---|---|
| `/wallpaper` | Lively Wallpaper | none | ignored | read-only client |
| `/screensaver` | `.scr` wrapper | captions | any input exits | read-only client |
| `/tv` | Chromecast tab cast, or TV browser | captions plus summonable overlay | remote D-pad, gamepad | read-only for the world, controls its own camera |
| `/god` | William, installable as a PWA window | full | mouse, keyboard, touch, gamepad | the only route that sends world-changing commands |
| `/share#ptk=...` | anyone, static page | designer preview only | mouse, touch | runs without a host (section 2.5) |

The god window should be built with **Preact plus `@preact/signals`** (about 5 KB gzipped, with fine-grained updates so a 10 Hz brain stream does not re-render the page). It should use **uPlot** for time series (https://github.com/leeoniya/uPlot) and plain Canvas 2D for the phylogeny, trophic web and brain graph. The tank viewport is the shared WebGPU or WebGL2 renderer from the rendering section. Budget: under 300 KB of gzipped JavaScript for the god UI on top of the renderer.

### 0.4 Who may change the world

The host accepts world-changing commands only from a **god client**.

- A page on `localhost` gets the god token automatically. The host injects it into the page it serves.
- A device on the LAN (laptop, phone) pairs once. The host shows a 6-digit code in the god window on the PC, and the device enters it.
- Wallpaper, screensaver and TV are always viewer role.
- If two god windows are open, commands are serialised by the host, last writer wins, and each window shows a small "changed by laptop" toast. This is rare and simple, so no locking is needed.

## 1. Creature designer

### 1.1 One genome, two editors

The designer edits a `DesignDoc`. Both modes are views of `doc.genome`. Neither keeps a shadow copy.

```ts
interface DesignDoc {
  id: string;                  // local uuid
  genome: Genome;              // single source of truth
  name: SpeciesName;           // section 6.4
  notes: string;               // up to 1 KB
  origin: 'template' | 'blank' | 'imported' | 'captured' | 'forked';
  parents: Fingerprint[];      // design lineage (what it was forked or captured from)
}
type GenomePatch = { before: Uint8Array; after: Uint8Array; label: string };   // bytes are small, so whole-genome undo is fine
```

The edit loop runs once per animation frame at most:

```
input event -> setLocus / editGrowth -> new Genome -> push GenomePatch (coalesced while dragging)
            -> develop(g, previewAge) -> Phenotype -> energyBudget(phenotype, env) -> validate()
            -> re-render sliders, part view, budget, issues; testTank.reset if "auto-restart" is on
```

**Ownership.** Each locus has `owner: 'genes' | 'parts' | 'both'`. Both modes display every locus they know about, but a locus owned by the other mode shows as a read-only chip with a jump link. For example, the gene panel shows "Eyes: 2 pairs (edit in parts)", and the part panel shows "Eye acuity 0.6 (edit in genes)". Loci marked `both`, such as fin area scale, are editable in either place and write the same bytes. Because nothing is cached between modes, the two modes cannot drift out of sync.

**Undo.** There is one stack for both modes: 200 entries, with a slider drag or a part drag coalesced into one entry. Ctrl+Z and Ctrl+Shift+Z work in either mode.

### 1.2 Gene sliders

There are two kinds of control, and the difference is shown in the UI:

- **Gene sliders** set one locus directly.
- **Instinct dials** set biases on the brain genome's initial wiring. Behaviour is heritable and evolves (see the brain section), so "aggression" is a starting instinct, not a fixed trait. Each dial maps to a fixed set of connection weights or output biases in the initial brain. For example, aggression adds `+k * dial` to the bias of the `attack` output and to the weight from `sight.preyNear` to `attack`. Each instinct dial is labelled "starting instinct, may evolve".

Each slider shows three values where they exist: the **gene value**, the **predicted phenotype** (from `develop`), and the **measured phenotype** (from the test tank, marked with a small flask icon once a test run has finished).

- Log sliders use a log scale and show the value in physical units.

- Typing a number into the value box clamps it to the range.
- Hovering a slider shows its sensitivity (section 1.4).

### 1.3 Part editor

The genome is a growth recipe. The part editor therefore edits **rules**, not instances, while letting William point at instances. Clicking a fin selects the rule that grew it and highlights every copy that rule produced ("this fin comes from rule F2 and appears 6 times"). The editor offers **Break out**, which duplicates the rule so that one copy can differ. Under the hood this inserts a new growth rule scoped to that segment index, so the change remains a genome edit.

**Skeleton.** `develop(g, 1.0)` grows the adult skeleton. That is a chain or tree of segments, each with **sockets** (attachment points) at fixed angles: dorsal, ventral, left and right lateral, anterior and posterior. The schema says which sockets each part type accepts.

| Part | Sockets | Editable properties (become loci or growth rule params) | Effect in physics or ecology |
|---|---|---|---|
| Segment | posterior of a segment | length, width, stiffness, repeat count, taper | body plan, drag, flexibility |
| Fin | lateral, dorsal, ventral, posterior | area, aspect ratio, stroke phase offset | thrust and turning |
| Tail | last posterior socket | type (fluke, ribbon, whip), area, stroke amplitude | main thrust for most plans |
| Eye | anterior, lateral | size, field of view, colour vs low light | sight inputs to the brain |
| Mouth | anterior only | type: rasp (grazing), jaw (bite), comb (filter), proboscis (parasite), scoop (detritus); gape | what it can eat and the handling time |
| Spike | dorsal, lateral, posterior | length, count | defence damage, drag |
| Light organ | any | type: photophore, lure (on a stalk), counter-shading strip; intensity | signalling, lure input for prey brains, energy cost |
| Gut (internal) | body cavity | volume | assimilation and storage |

Interactions:

- Drag a part from the palette over the skeleton. Valid sockets glow, the part snaps to the nearest valid socket within 24 px, and an invalid drop springs back with a tooltip.
- The symmetry mode is a body-level locus: bilateral (default), radial 3 to 8, or none. Placing a part on one lateral socket mirrors it.
- Repetition: set "repeat on segments 2 to 6" from the part's context menu. This writes the rule's segment mask.
- Delete or Backspace removes the selected rule. Ctrl+D duplicates it.
- Parts can be dragged along the segment chain to move them. Handles control size and angle.

**Live preview.** There are two panes, both always running:

1. **Growth strip.** An age scrubber from 0 (newborn or bud) to 1 (adult) with keyframes at 0, 0.25, 0.5 and 1. Pressing play loops the growth over 6 s, so William sees how the juvenile looks and whether a part only appears late. It uses `develop(g, age)`, which takes at most 5 ms on a weak laptop, so it re-renders on every scrub frame.
2. **Test tank.** A real `TestTank` instance in a Web Worker. It holds one creature (or two for mating tests) in a 30 by 20 body-length box.
   - Scene presets: *open water*, *food patch*, *dummy predator* (a scripted chaser), *dummy prey*, *current* (a uniform flow at 0.5 body lengths per second) and *dark* (light 0.05).
   - Measured readouts update live: top speed, cruise speed, turning radius, cost of transport (energy per body length), time to reach food, and survival time against the dummy predator.
   - Budget: about 2 ms per step on the CPU for one creature plus 20 scripted entities, run at 60 Hz on the 5090 PC and 30 Hz on a weak laptop.
   - The tank restarts automatically 300 ms after the last edit, with a fixed seed so that comparisons between edits are fair. A "reroll seed" button is available.

### 1.4 Energy budget readout

The readout is an estimate from the phenotype, using the same coefficients as the sim. The coefficient values belong to the sim section; the equation shapes are what the UI needs.

Costs (power, in energy units per sim second):

- `P_basal = k_b * M^0.75 * Q10^((T - T_ref)/10)`. This is Kleiber scaling with Q10 of about 2. T comes from the chosen zone.
- `P_tissue = sum over parts of c_type * m_part`. Here c is per tissue type: muscle > eye > fin > skin > spike.
- `P_brain = c_n * neurons + c_s * synapses`
- `P_glow = c_g * intensity * area * dutyCycle`
- `P_swim = (0.5 * rho * C_d * A * v^3) / eta`, at the cruise speed v. C_d and A come from the grown shape, and eta comes from the fins. Once the test tank has a measured value, it replaces the formula and is marked with a flask.
- `P_growth` (juvenile only) and `P_repro = clutch * E_child / interval`

Income:

- The intake rate follows a Holling type II response: `f(rho_f) = a * rho_f / (1 + a * h * rho_f)`, times the assimilation efficiency.
- The search rate `a` is approximately sensor range times speed times the width swept. The handling time `h` comes from the mouth type and the prey size ratio.
- Income is evaluated at three food densities: **poor**, **typical** and **rich**. When connected to a live world, these are the 10th, 50th and 90th percentile of current food density in the chosen zone, so the readout reflects William's actual tank. Otherwise defaults are used.

Derived numbers shown:

- the break-even food density `rho*` (where net = 0)
- starvation time = E_store / total cost
- time to maturity
- the expected interval between reproduction events
- a rough lifetime offspring count at typical density

```
+-- Energy budget (estimate) ------------------------------------------------+
| Income   poor  ####........ 0.8      typical ########.... 2.1   rich ...3.4 |
| Costs    basal ###  muscle #####  brain #  eyes ##  glow #  repro ###  =1.9 |
|          ^ break-even food density: 0.42 /m2   (zone median: 0.61)          |
| Starves in 3.1 days   Adult in 4.0 days   Breeds every 2.2 days            |
| Lifetime offspring (typical): ~11                                           |
| Top trade-offs  [muscle +10%: speed +6%, cost +9%]  [glow -0.2: cost -4%]   |
+-----------------------------------------------------------------------------+
```

**Trade-off chips.** For the hovered slider, and for the three loci with the largest absolute `d(net)/d(locus)`, the readout computes central finite differences (±5% of range). That costs 6 extra `develop` plus budget calls, about 15 ms on a laptop, and runs in an idle callback. Each chip reads "if you change X by +10%: speed +6%, net energy -9%".

### 1.5 Validation: warn, never forbid

`validate(phenotype, budget, releasePlan)` returns `Issue[]` with three severities: `info`, `warning` and `inviable`. The release button is always enabled. If any `inviable` issue exists, its label changes to "Release anyway", and the species record is tagged `predictedInviable` so the timeline can later say "predicted inviable, survived 40 generations".

| Id | Condition | Severity | Message (English key text) |
|---|---|---|---|
| V01 | net energy < 0 at *rich* density | inviable | "Starves even in rich water." |
| V02 | net < 0 at *typical* density | warning | "Needs richer water than this zone usually has." |
| V03 | the mouth type cannot eat any item on the diet (for example a comb mouth with 100% meat) | inviable | "Its mouth cannot eat what it wants to eat." |
| V04 | no thrust and no filter or parasite strategy | warning | "Cannot swim; it will drift with currents." |
| V05 | sexual bias > 0.95 and release count < 2 | inviable | "Mating only, but you are releasing a single individual." |
| V06 | child energy > the adult's storage capacity | inviable | "Cannot store enough energy for even one offspring." |
| V07 | no brain path from any sense to any motor output | warning | "Its brain cannot react to anything yet." |
| V08 | the grown body self-intersects or a part sits on an invalid socket | warning | "Parts overlap; physics will separate them." |
| V09 | preferred temperature is outside the world's current range everywhere | inviable | "No zone in this world is warm or cold enough." |
| V10 | genome distance < the speciation threshold from an existing living species | info | "Very close to *Pratilux tondens*; they may interbreed." |
| V11 | mutation rate > 0.05 | warning | "Error catastrophe likely: offspring will often be broken." |
| V12 | pulse rate × glow area exceeds the flash-safety envelope | info | "Pulse will be softened on screen (safety cap)." |

Clicking an issue highlights the responsible slider or part.

### 1.8 Designer state model

```ts
type DesignerMode = 'genes' | 'parts';
interface DesignerState {
  doc: DesignDoc;
  savedHash: Fingerprint | null;           // dirty = hash(doc.genome) !== savedHash
  mode: DesignerMode;
  selection: { rule: string; instance?: number } | { locus: string } | null;
  previewAge: number;                      // 0..1
  growthPlaying: boolean;
  tank: { scene: TestSceneId; seed: number; status: 'running' | 'restarting' | 'error'; measured?: Measured };
  history: { undo: GenomePatch[]; redo: GenomePatch[] };   // cap 200
  // derived: recomputed from doc.genome, never stored or sent
}
```

| From | Event | To | Side effects |
|---|---|---|---|
| Closed | open(template, captured genome or file) | Editing (clean) | develop, budget, validate; start the tank |
| Editing | edit | Editing (dirty) | push patch; debounce tank restart by 300 ms |
| Editing | switch mode | Editing | none (same genome) |
| Editing | save | Editing (clean) | write `.ptk` to the host library (section 2) |
| Editing | release... | ReleaseDialog | the dialog shows issues and the plan |
| ReleaseDialog | confirm | Editing | send `ReleaseCmd`; auto-save to the library if dirty |
| Editing | close while dirty | ConfirmDiscard | the draft is kept in IndexedDB as a per-viewer convenience |

### 2.1 Release flow

`ReleaseCmd { genome, name, count: 1..500, placement: ZonePref | Point | Scatter, energy01, designFingerprint }`.

What the host does with it:

- It creates a new species record, always. The record is tagged `origin: designed | imported | captured`, and the species is never silently merged into an existing one. If the design is within the speciation threshold of an existing species, issue V10 says so. The speciation section may later merge or split the record as genomes drift; the record keeps `foundedBy: design fingerprint`.
- Each founder gets small independent mutations at release, at 1x its mutation rate, so the founders are not perfect clones. A "clonal founders" checkbox under Advanced turns this off.
- It emits a `WorldEvent{kind:'release'}`. Every view sees it, and the screensaver director treats it as a medium-priority "new arrivals" event.

Releases are free and unlimited by default. A balancing knob can impose a release budget (section 3.10).

### 2.2 Species library

The library is a folder on the host disk, `<data>/library/`. It holds one `.ptk` file per design plus `index.json`, so it is git-friendly. It lives outside the world, so rewinding the world never touches it. Because the folder is plain files, a community could keep a shared bestiary as a public git repo of `.ptk` files with no server.

```
+-- Library -----------------------------------------------------------------------------------+
| [Search name, tag, niche...]  [All v] [Designed] [Captured] [Imported] [Templates]  [Import]  |
|-----------------------------------------------------------------------------------------------|
| (thumb) Pratilux tondens     Meadowlamp    grazer     template   fp 3fa9-12c0   [Edit][Share] |
| (thumb) Tacitostoma insid.   Hushmaw       predator   template   fp 81d2-77ab   [Edit][Share] |
| (thumb) Pratilux tondens f.  "Bluefin"     grazer     captured   gen 412, day 31 [Edit][Share]|
| (thumb) Lumivora spinata     -             predator   imported   from: file      [Edit][Share] |
|-----------------------------------------------------------------------------------------------|

```

Thumbnails are not stored. They are regenerated from the genome by `develop(g, 1)` and rendered to a 96x64 canvas. That keeps the files small and the thumbnails always correct.

**Capture from the world.** In the inspector, "Save genome to library" copies a living creature's current evolved genome into a new entry. The entry has `origin: captured` and records the world name, day, generation and species. This is how William shares what evolution made, not just what he designed.

### 2.3 File and string format (`.ptk`, `PTK1.` strings)

There are no accounts or servers. Sharing is a file or a text string that can travel by chat, email, forum, QR code or git.

Binary container, little-endian:

| Offset | Size | Field |
|---|---|---|
| 0 | 3 | magic `PTK` |
| 3 | 1 | container version (1) |
| 4 | 1 | kind: 1 = single design, 2 = pack (up to 64 designs), 3 = world-snapshot reference (file only) |
| 5 | 1 | flags (bit 0: compressed) |
| 6 | 2 | genome schema version |
| 8 | 4 | payload length |
| 12 | n | payload: deflate-raw (`CompressionStream`) of CBOR `{meta, genome}` |
| 12+n | 4 | CRC32 of bytes 0 to 12+n |

`meta` = `{ name: {genus, epithet, common?}, notes?, author?: free-text handle, created: ISO date, origin, parents: [fingerprint], tags: [string], world?: {name, day, generation} }`.

**Fingerprint.** This is the first 8 bytes of SHA-256 over the canonical genome bytes, shown as `3fa9-12c0-88e1-04bd`. It identifies a creature across tanks and is used to de-duplicate the library. Two people can compare fingerprints to confirm that they hold the same creature.

**String form.** The string is `PTK1.` followed by base64url of the container. Expected sizes: a genome of 1 to 4 KB raw, about 0.5 to 2 KB after deflate, so a string of roughly 0.7 to 2.7 K characters. That fits in a chat message, and a typical design fits a QR code (version 40 holds about 2.9 KB binary at the lowest error correction). The share dialog shows the QR code only when the string is under 2,300 bytes, and offers the file otherwise.

**Share link.** `https://tengilourliberator.github.io/phylotank/share#ptk=PTK1.xxxx`. The creature lives in the fragment, which browsers never send to the server, so this is static hosting with no server logic. The share page runs the designer preview and test tank standalone, and offers *Copy string* and *Download .ptk* for importing into your own tank. Whether the page can hand off directly to a local host is open question 5.

```
+-- Share Pratilux tondens --------------------------------------+
|  fp 3fa9-12c0-88e1-04bd                                         |
|  [Copy string]  PTK1.eJzT0dXV...  (1,412 chars)                 |
|  [Copy link]    https://...github.io/phylotank/share#ptk=...    |
|  [Save .ptk file]          [Show QR]                            |
|  [x] include notes   [ ] include world info (name, day)         |
+-----------------------------------------------------------------+
```

### 2.4 Import safety

Imported files and strings are untrusted data.

- Input is capped at 64 KB raw and 256 KB decompressed. The decompressor aborts past the cap, which protects against zip bombs.
- The CRC must match. The CBOR parser is strict, with no extension tags.
- The genome must decode under the schema. Loci are clamped to their legal ranges, and a list of clamped loci is shown.
- Schema migration: older schema versions go through `migrate[v]`, a pure function per version. A newer schema is refused with "made with a newer Phylotank (schema 7); update to import".
- Text fields are NFC-normalised. Control characters and bidi overrides (U+202A to U+202E, U+2066 to U+2069) are stripped. Names are capped at 40 characters and notes at 1 KB. Text is rendered as text, never HTML.
- An import always opens in the designer preview first. It never goes straight into the world.

### 3.3 Time control and the speed lease

The speed controls are pause, 1x, 4x, 16x and **max**. Max runs the sim unthrottled, and views get decimated state.

The world is shared, so a fast-forward also speeds up the wallpaper and the TV, and a paused world freezes them. To keep the wallpaper calm by default:

- Any speed other than 1x is a **lease** held by a god window. The window renews it every 10 s, and the lease expires after 30 s without renewal.
- When the god window closes, crashes or sleeps, the world returns to 1x.
- Pause follows the same rule by default. The world resumes at 1x when the god window goes away. The setting "Keep paused after closing" is off by default.
- Non-god views show nothing about the speed. The screensaver and TV may add the caption "Time is running 16x faster" once per change (section 4).

`SetSpeedCmd { speed: 0 | 1 | 4 | 16 | 'max', leaseMs: 30000 }`. The god window displays the actual achieved speed ("16x requested, 11.3x achieved"), which matters on a weak laptop.

### 3.5 Inspector

Selection works by clicking in the viewport. The renderer does ID picking: it writes entity ids to an offscreen target and reads back one pixel. That costs one extra pass only on a click, under 1 ms. The client sends `SelectCmd{entityId}`, and the host then streams detail for the selected creature (up to 4 pinned creatures) at 10 Hz, about 2 KB each per tick.

Inspector tabs:

- **Overview.**
  - Identity: species name, the individual's number, life stage, age, generation.
  - State: energy bar (store and current net), health, active infections, current action from the brain's top output.
  - History: number of offspring, distance travelled, kills or meals.
  - Actions: Follow (the camera tracks it), Save genome, Fork in designer, Bookmark, Bless, Rename species.
- **Genome.** A gene table grouped as in the designer. Each row shows the individual's value, the species mean ± sd, and a delta marker against the founder design (or against the species' first sampled genome for natural species). "Show only differences" is on by default.
- **Body.** The grown body drawn large with labelled parts. Hovering a part highlights it on the creature in the viewport. A "sense overlay" toggle draws the creature's vision cones, smell radius and lateral-line radius in the viewport.
- **Brain.** A live network diagram.
  - Inputs sit on the left, grouped by sense (eyes, smell, flow, touch, internal energy, clock), and outputs on the right (thrust, turn, mouth, attack, mate, bud, glow).
  - Hidden neurons are placed by longest-path layering from the inputs, with back edges ignored. Recurrent edges are drawn as arcs.
  - Edge colour shows the sign of the weight (with a dashed pattern for negative, so colour is not the only cue), and thickness shows |w|. Node brightness shows the live activation.
  - Activations are streamed as int8 at 10 Hz. Up to 512 nodes and 4,096 edges are drawn with Canvas 2D, at about 1 to 2 ms per frame.
  - A 10 s activation trace can be shown for any node.
  - Prior art for this kind of view: NEAT network visualisations (Stanley and Miikkulainen 2002, https://nn.cs.utexas.edu/downloads/papers/stanley.ec02.pdf) and the Avida-ED organism viewer (https://avida-ed.msu.edu/).
- **Kin (lineage and family tree).**
  - The ancestor chain runs back to the founder, with long unbranched stretches collapsed ("... 213 generations ...").
  - It shows parents (one for a bud, two for a mating), siblings alive, children, and grandchildren alive.
  - The family tree view shows 3 generations up and 2 down, with expandable nodes. Dead individuals appear as hollow nodes.

```
+-- Inspector: #48213 ------------+
| Pratilux tondens   adult, 3.2 d |
| [Over][Genome][Body][Brain][Kin]|
|---------------------------------|
|  eyesL o--.                     |
|  eyesR o---\---( )----o thrust  |
|  smell o----X--( )--\-o turn    |
|  energy o--/---( )---\o mouth   |
|  clock  o-'        '--o mate    |
|  (bright = active, dashed = -w) |
| trace: thrust ~~/\~~~/\~~~      |
+---------------------------------+
```

**Genealogy storage**, which the host needs in order to answer Kin queries. The host keeps parent links in a pruned genealogy. Nodes are kept only if they are alive or have at least two lineages with living descendants. Unary chains are compressed into edges with a generation count. That bounds the store at under 2N nodes for N living creatures: at N = 200k with 32 B per node, about 13 MB. This is the same idea as tree-sequence simplification in tskit (Kelleher et al. 2018, https://tskit.dev/). Dead individuals are retained in full for the last 10 sim-minutes, so the inspector can show recent deaths. Per-individual history further back exists only in snapshots.

### 3.6 Stats

The host records stats in multi-resolution ring buffers, in the style of RRDtool:

| Resolution | Kept for |
|---|---|
| 1 s | last hour |
| 1 min | last 30 days |
| 1 h | all time |

Each species uses 4 to 16 B per sample. At 500 species this totals under 30 MB, and extinct species are frozen and compressed. A stats subscription streams one update per second, at 4 to 20 KB.

```
+-- Stats -----------------------------------------------------------------------------------+
| [Population] [Phylogeny] [Food web] [Genes] [Diversity]          range: [1h][1d][30d][all] |
|--------------------------------------------------------------------------------------------|
| Population per species (stacked, log toggle)                                               |
| 40k |            ____________                                                              |
|     |   ________/ Pratilux   \______        ___                                            |
| 20k |  /   Cineralegus ...           \_____/   \___                                        |
|     | /____Tacitostoma_____________________________                                        |
|   0 +------------------------------------------------ time                                 |
|        ^meteor        ^new species: Pratilux caerula                                       |
+--------------------------------------------------------------------------------------------+
```

- **Population per species over time.**
  - A stacked area chart in uPlot, with the top 12 species by current biomass named and the rest grouped as "other".
  - Toggles switch between linear and log scales, and between counts and biomass.
  - World events are drawn as vertical markers from the same event stream as the timeline.
- **Phylogeny tree.**
  - A species-level tree with time on the x axis. Each branch starts at a speciation event (from the speciation section's clustering) and ends at extinction (a ×) or continues to "now".
  - Branch thickness is log population, which makes it a spindle or fish plot in the style of Miller et al. 2016 (https://github.com/chrisamiller/fishplot).
  - Leaf order follows a tidy layout in depth-first order with stable sorting, so the tree does not jump between updates. Layout is incremental, O(new nodes).
  - Founders are marked: designed ◇, imported ○, natural •.
  - Clades that died out completely collapse into thin ghost lines, which expand on click.
  - Clicking a branch filters every other chart and the minimap to that species.
  - Semantic zoom keeps up to about 5,000 drawn nodes at 60 fps on the 5090 and about 1,500 on a laptop, coarsening beyond that.
- **Trophic web.**
  - Nodes are species, with size showing biomass, plus three abiotic nodes: plankton, plants and detritus.
  - The y position is the trophic level `TL_j = 1 + sum_i w_ij * TL_i`. Here `w_ij` is the fraction of j's energy intake that came from i over the last 10 sim-minutes, and plankton, plants and detritus have TL = 1 (the Ecopath convention).
  - TL is computed by solving `(I - W^T) TL = 1`, which is trivial at S ≤ 500.
  - The x position comes from a force layout seeded by the previous frame. Edge width shows log energy flow, and parasitism is drawn as a dotted edge.
  - The host aggregates feeding events into a sparse S×S matrix.
- **Gene histograms.**
  - Pick a gene and one or more species to see a 32-bin histogram now.
  - A "drift heatmap" shows time on x, gene value on y and density as brightness, sampled every sim-minute. It shows selection pushing a trait, for example adult size creeping up in Deepcrown.
- **Diversity.**
  - Species richness S.
  - Shannon `H' = -sum p_i ln p_i`, shown with its effective number of species `exp(H')`.
  - Simpson `1 - sum p_i^2`.
  - Within-species genetic diversity: the mean pairwise `genomeDistance` over 256 sampled pairs per species per minute.
  - All are plotted over time, and every chart has a "Show as table" toggle for accessibility.

### 3.8 Bookmarks and rewind

Snapshots are written by the host. The format, size and compression belong to the architecture section. The UI needs only `{id, name, tick, epoch, createdAt, kind: manual | auto | beforePower | beforeRewind, thumbnailPng, populations, bytesOnDisk, parentId}`.

```
+-- Bookmarks ------------------------------------------------------------------+
| [Bookmark now  Ctrl+B]                   disk: 1.8 GB of 10 GB  [retention...] |
|-------------------------------------------------------------------------------|
| (img) Before meteor        day 14 07:18  auto    41k life  12 sp   [Rewind]   |
| (img) "First Hushmaw boom" day 12 22:40  manual  38k life  10 sp   [Rewind]   |
| (img) Autosave             day 12 20:00  auto    37k life  10 sp   [Rewind]   |
|   \-- (img) Before rewind  day 13 03:10  (branch)                  [Rewind]   |
+-------------------------------------------------------------------------------+
```

Rewinding creates a fork and never deletes the present. The state model:

```
Idle --Rewind(s)--> Confirm("All views will jump back to day 12. The present is saved as 'Before rewind'.")
Confirm --yes--> Rewinding: host autosaves present (kind beforeRewind, parentId = current),
                 pauses, loads s, epoch += 1, broadcasts {kind:'worldReset', epoch}
Rewinding --host ready--> Idle (resumes at previous speed, or 1x if no lease)
```

When a view receives `worldReset`, it drops its interpolation buffers. The wallpaper and screensaver do a slow 1.5 s fade through black with no text. The TV shows the caption "Rewound to day 12". The species library is unaffected.

Retention defaults: an autosave every 30 sim-minutes, keeping the last 24; all `beforePower` and `beforeRewind` snapshots for 7 real days; manual bookmarks forever.

## 4. Views with no UI or minimal captions

### 4.1 Wallpaper: none

There is no DOM UI, text, cursor reaction or tooltip. Mouse input forwarded by Lively is ignored. A cursor-as-light-source option exists under Views settings, off by default, and is not UI as such.

The error behaviour is also silent:

- If the host is unreachable, the page runs a small in-page **dream tank**: a 2,000-creature local sim seeded from the templates. It retries the host with backoff (0.5, 1, 2, 4, then 10 s maximum). When the host returns, the page crossfades back over 1.5 s.
- No error text is ever shown. Diagnostics live in the god window ("Wallpaper: 1 connected, last seen 2 s ago") and at `?debug=1`.

### 4.2 Screensaver: captions only

When the director frames an event, the screensaver shows one lower-third caption:

- The species name is shown in italics, followed by a short line, for example "*Tacitostoma insidians* · a hunt in the twilight zone".
- Timing: a 1 s fade in, a 5 s hold and a 1.5 s fade out, with at most one caption per 45 s. Priority comes from section 3.7.
- Text height is 2.2% of the screen height. It is drawn in white at 70% opacity on a 40% black gradient band.
- Captions are on by default, with an off switch in settings. An optional small clock in a corner is off by default.
- Standard `.scr` behaviour: any key, click or mouse movement beyond 8 px exits.

## 5. Onboarding for public users

### 5.1 Goal and budget

From first launch to a living, balanced tank on screen should take **under 10 s** on William's PC and **under 60 s** on a weak laptop running in browser-only mode, with no reading required.

| t | What the person sees | Mechanism |
|---|---|---|
| 0 s | dark water, drifting particles, a soft vignette | renderer starts without a world (ambient mode) |
| < 3 s (PC) | creatures swim in | load the bundled **Founding Waters** snapshot (1 to 3 MB) |
| ~10 s | a small non-blocking welcome card at the bottom | |
| any time | optional 3-step tour: click a creature, try a power, open the designer | coach marks, each dismissible |
| after the tour | "Make it your wallpaper / screensaver / TV" card | setup steps per the architecture section |

**Founding Waters** is a snapshot shipped with the app. It holds the six template species plus plankton, already run for 2 sim-hours so that populations sit near equilibrium and there is some variation. On load, the host perturbs the RNG seed, so every user's tank diverges from that point.

If the snapshot's schema is incompatible, the host uses **procedural seeding** instead:

1. Initialise plankton at the analytic logistic steady state for each light level.
2. Place each template species in its preferred zone, with counts from Damuth's law (`N ∝ M^-0.75`), scaled to the target biomass for the measured hardware budget.
3. Run 30 s at max speed behind a fade-in, to burn off transients.

### 5.2 Onboarding state model

The flags `onboarding.version`, `tourDone` and `viewsSetupDismissed` are stored on the host (world-independent config). A per-viewer `localStorage` mirror covers the browser-only mode.

```
FirstRun --world exists?--> no: Seeding(snapshot | procedural) --> Welcome
                            yes: Welcome (or Done if tourDone)
Welcome --"Show me around"--> Tour(1: inspect) --> Tour(2: power, suggests Algae bloom, a harmless one)
        --> Tour(3: designer, opens Meadowlamp) --> SetupViews --> Done
Welcome --"Just watch" / 20 s idle--> Done (card shrinks to a "?" in the top bar)
any Tour step --Skip--> Done
Welcome --"Start empty instead"--> confirm --> new world with plankton only --> Done
```

The tour never asks the person to read paragraphs. Each step is one sentence and one highlighted control, and completing the action advances the tour.

### 5.3 Browser-only mode

Someone trying Phylotank from the static site can run the sim inside the page, in a worker using WebGPU if available. Population is capped by a 5-second benchmark at first run. The UI is identical, except that the top bar shows "Running in your browser; install the host for wallpaper, screensaver and TV". The library is stored in IndexedDB, with export to `.ptk` files encouraged.

## 6. Accessibility, input, localisation and naming

### 6.1 Accessibility

- **The UI does not rely on colour.** Creature colours are genetic and arbitrary, so every species also gets a stable **glyph** (one of 24 shapes, assigned by species id) and its name. Charts use glyphs, direct labels and dash patterns.
- A "chart palette" option replaces genetic hues in charts with a colour-vision-deficiency-safe categorical palette.
- A view-wide colour-vision filter (protan, deutan, tritan remap) is available for the tank itself.
- **Contrast.** UI text meets WCAG 2.2 AA (4.5:1, or 3:1 for large text and UI components) (https://www.w3.org/TR/WCAG22/). A high-contrast theme removes translucency.
- **Photosensitivity.** This applies to every view, not just the UI.
  - No region larger than 25% of the screen may change luminance by more than 10% more than 3 times per second, following WCAG 2.3.1 "three flashes".
  - Creature pulse rate is capped at 2 Hz in the genome range.
  - The renderer low-passes the aggregate luminance of large glowing swarms.
  - Meteor and lightning-like effects use a single slow bloom (at least 300 ms rise) instead of strobing.
  - These caps are tested automatically (section 7).
- **Reduced motion.** `prefers-reduced-motion`, or the in-app toggle, removes UI transitions and camera swoops (cuts replace them). It also halves pulse amplitude and slows the screensaver director's camera moves.
- **Screen readers.** All panels are DOM with ARIA roles; only the viewport, minimap and charts are canvases.
  - Each canvas has a text alternative. The viewport has a "Describe view" button and a polite live region, for example: "Viewing the twilight zone, 340 creatures, mostly *Cineralegus sedulus*; selected: Hushmaw #881, hunting."
  - Every chart has a data-table view.
  - Power targeting can be done entirely through form fields: zone or coordinates, radius, intensity.
  - The test target is NVDA on Windows with Chrome.
- **Motor.** Every drag has a keyboard equivalent. Hold-to-confirm has a dialog-button alternative. All hit targets are at least 32x32 px (44 px in touch layout).
- **Text size.** UI scale runs from 75 to 200%. Layouts reflow, and nothing is clipped at 200% on a 1280 px window.

### 6.3 Localisation (English and Swedish first)

- Strings live in `locales/en.json` and `locales/sv.json` as ICU MessageFormat, using the `@formatjs/intl-messageformat` runtime or an equivalent. Pluralisation uses `Intl.PluralRules`, and numbers and dates use `Intl.NumberFormat` and `Intl.DateTimeFormat`. In `sv-SE` that gives a decimal comma and a space as the thousands separator.
- Units are metric everywhere.
- The language defaults to `navigator.language` and falls back to English. It can be switched in Settings without a reload.
- Captions and timeline sentences are whole templates with slots, never concatenated fragments. That allows for Swedish word order and definite forms.
- Binomial species names are not translated. Common names are generated per locale (section 6.4).

### 6.4 Species naming

Every species gets a **binomial-style name**, *Genus epithet*, generated deterministically from `(worldSeed, speciesId, trait vector)`. Each name is original, so it is not copied from real taxa or from any franchise.

**Genus.** A daughter species inherits its parent's genus. A new genus is minted only when `genomeDistance` from the genus founder exceeds `genusThreshold`, which is 3x the speciation threshold. This mimics real taxonomy and keeps names meaningful: *Pratilux tondens* can give rise to *Pratilux caerula*. A new genus is built as `root(dominant trait) + root(body plan) + suffix`:

| Trait | Roots (Latin or Greek-flavoured, original combinations) |
|---|---|
| diet: plant / meat / detritus / filter / parasite | prati-, phyto- / vora-, dentro- / cinera-, necro- / cribro-, saccu- / haeru-, tethi- |
| zone: photic / twilight / midnight | lux-, sol- / umbra-, crepu- / bathy-, nocti- |
| body plan: long / round / radial / huge | -caulus, -soma / -sphaera, -bulla / -stella, -campana / -titan, -corona |
| suffix | -a, -ella, -opsis, -ides, -on |

**Epithet.** The epithet comes from the most distinctive trait relative to the parent species (the largest z-scored difference). It is drawn from adjective tables such as *caerula* (blue glow), *spinata* (spikes), *lenta* (slow), *velox* (fast), *profunda* (deeper), *gigantea* (bigger) and *tenebrosa* (lives in darkness). The adjective agrees with the genus gender, which is derived from the suffix. If the epithet is already used within the genus, a numbered variant from a second table is used.

**Common names.** These are generated per locale from the same traits, for example "blue-glow grazer" in English and "blåglödande betare" in Swedish. They are shown under the binomial.

**Checks**, enforced by tests (section 7):

- Names are pronounceable: no more than 3 consonants in a row, with the length limits below.
- A profanity and slur substring blocklist in English and Swedish.
- A blocklist of franchise creature names: Pokémon, Digimon, Spore, The Bibites and kaiju names, compiled at build time.
- An exact-match check against a bundled list of about 50k real genus names (GBIF backbone, compressed to about 300 KB). A collision rerolls the root choice. Real epithets are fine, because they are ordinary Latin adjectives.

**Renaming.** William can rename any species from the inspector, the library or the phylogeny.

- He can change the genus, the epithet, the common name or any combination. A genus rename can optionally apply to the whole genus.
- Rules: genus 3 to 24 letters and capitalised, epithet 3 to 24 letters and lowercase, letters plus hyphen only. The name must be unique among living and recorded species, and a warning (not a block) appears otherwise.
- A user-set name is flagged `namedBy: 'user'`. Daughter species inherit a user-named genus.
- Each rename is a `WorldEvent` and is written into captured `.ptk` files.
- Display: the binomial is in italics wherever text styling exists, and plain text with the same capitalisation elsewhere.

## 8. Failure modes and how the UX handles them

| Failure | Handling |
|---|---|
| The host is down while the god window is open | Banner "Host not running", with retry and backoff; world-changing controls disabled; the designer and library still work offline; on reconnect, re-subscribe and reload state for the current epoch |
| A command is lost in transit | Every command carries a client `opId`; the host acks it with an event id; the client retries idempotently by `opId` within 10 s |
| A rewind happens while another god window is mid-cast | The host rejects commands with a stale epoch; the client shows "World was rewound; power not cast" |
| Bad `.ptk` or string | A specific error message (section 2.4); never a partial import |
| Schema change between versions | Migrations on import; library files are migrated lazily on open; the original is kept as `.bak` |
| Weak hardware cannot reach the requested speed | Achieved speed is shown; max mode adapts the step batch to keep views at 15 fps or more |
| Name generator collision or blocklist hit | Deterministic reroll with a salt; after 16 attempts, a numbered fallback (`Pratilux sp. 17`) |
| Stats memory grows over months | Extinct species are frozen and compressed; the 1 h tier is kept forever at about 9 KB per species per year |
| A fast-forward lease is orphaned | Expires after 30 s and the world returns to 1x |
| A photosensitivity cap would change the look of a design | Applied only at render time; the genome is untouched (V12 informs) |

## 9. Tests

Unit tests use Vitest with property-based tests from fast-check. End-to-end tests use Playwright, with a headless host started from a fixture world. Accessibility checks use axe-core plus manual NVDA passes.

**Designer and genome bindings**

- UX-T01 *Slider round trip.* For random genomes g and every locus with `ui`: `getLocus(setLocus(g, id, v), id) == clamp(v)`, and every other locus is unchanged (property test, 10k cases).
- UX-T02 *Single source.* Apply a random sequence of slider and part edits, switch mode after each one, and compare: the rendered value in both modes equals `getLocus` of the current genome.
- UX-T03 *Undo.* For a random edit sequence of length 1 to 200, undoing all edits restores the original bytes exactly. Redoing all edits restores the final bytes.
- UX-T04 *Rule vs instance.* Editing a repeated fin rule changes all N copies in `develop` output. "Break out" changes one copy, and the other N-1 copies stay byte-identical in their phenotype.
- UX-T05 *Snapping.* Every part type dropped on every socket either attaches (when the schema allows it) or is rejected. No socket accepts a type that the schema forbids.
- UX-T06 *Budget sanity.* Increasing muscle never lowers `P_tissue`. Increasing size raises `P_basal` with an exponent within 0.75 ± 0.01 (fitted over 20 sizes). Break-even density is monotonic in total cost.
- UX-T07 *Validation coverage.* One fixture genome per rule V01 to V12 triggers exactly that issue. The release button stays enabled for every fixture.
- UX-T08 *Estimate vs measurement.* For the 6 templates, predicted cruise speed is within ±35% of the test-tank measurement. This catches drift between the UI formulas and the physics.

**Library and sharing**

- UX-T10 *Format round trip.* Encode and decode equals identity for random designs. The fingerprint is stable across encodings.
- UX-T11 *Size.* All templates, and 1,000 random evolved genomes from a soak world, produce `PTK1` strings of 3,000 characters or fewer. The 95th percentile is 2,000 or fewer.
- UX-T12 *Hostile input fuzz.* 100k mutated or truncated buffers produce no crash, no hang above 50 ms, and no import with an out-of-range locus. A zip bomb is rejected at the cap. Bidi and control characters are stripped.
- UX-T13 *Migration.* Fixture files from every past schema version import, and a newer version is refused with the correct message.
- UX-T14 *Share page offline.* The `/share#ptk=` page renders the preview with network requests blocked after load, so nothing is sent anywhere.

**God window and world** (end-to-end against the host)

- UX-T20 *Template viability.* Each template plus plankton, alone in a fixture world, persists for at least 60 sim-min at 1x in at least 95% of 40 seeds. Deepcrown is checked for growth instead: its mean adult size increases in at least 70% of 40 seeds over 30 sim-days with the global mutation multiplier at 1. Releasing all six together keeps at least 4 alive after 2 sim-hours in at least 80% of seeds.
- UX-T21 *Release propagates.* Releasing 40 individuals produces a species record, a `release` event in the god window, the wallpaper client and the screensaver client within 500 ms, and a timeline marker.
- UX-T22 *Power flow.* For every `PowerSpec`: Esc cancels at every state; a major power creates a `beforePower` snapshot before its effect tick; the preview count equals the host's count at the cast tick to within 5%.
- UX-T23 *Speed lease.* Set 16x, kill the god window process, and the world returns to 1x within 30 to 31 s. The wallpaper client observes the change.
- UX-T24 *Rewind.* After a rewind, the epoch increments, all clients reset, the present exists as `beforeRewind`, the library is unchanged, and a stale-epoch command is rejected.
- UX-T25 *Inspector.* Picking a creature returns the right entity id (render 1,000 entities, click each centre, require 99% or more correct). The brain stream stops within 1 s of deselection.
- UX-T26 *Genealogy.* In a 10k-creature soak run for 24 sim-hours, pruned genealogy nodes stay below 2N, and every living creature's ancestor chain reaches its founder.
- UX-T27 *Trophic level.* On a hand-built 4-species chain (plankton, grazer, predator, top predator), the computed TL values are 1, 2, 3 and 4 to within 0.01.
- UX-T28 *Diversity.* Shannon and Simpson values match reference values for fixture populations.

**Views, onboarding, accessibility, localisation**

- UX-T30 *Wallpaper has no UI.* The DOM of `/wallpaper` contains no text nodes, including when the host is down (dream-tank mode). A screenshot diff confirms no glyphs.
- UX-T31 *Caption cadence.* An event burst of 50 events in 60 s produces at most 2 captions in the screensaver, highest priority first.
- UX-T32 *Flash safety.* Record 10 min of each view during meteor, plague and bloom scenarios, and also a swarm of maximum-glow pulsers. A luminance-flash analyser in the style of the Harding test, run on frames, reports zero violations of the three-flashes rule.
- UX-T33 *Onboarding timing.* From a cold start to 50 or more creatures visible takes under 10 s on the reference PC and under 60 s on a throttled weak-laptop profile (Chrome CPU 4x slowdown plus a software-GPU fallback check). The tour can be completed or skipped with keyboard only.
- UX-T34 *Accessibility automation.* axe-core reports zero serious or critical violations in every god panel, in both themes, at 100% and 200% scale.
- UX-T35 *Keyboard-only script.* Design from a template, save, release, cast an algae bloom, inspect a creature, bookmark and rewind, all without a pointer.
- UX-T36 *Gamepad.* Using a virtual gamepad (Playwright-injected `navigator.getGamepads` mock), every TV overlay control is reachable, and Back hides the overlay.
- UX-T37 *Localisation.* No key is missing in `sv` or `xx`, and every message parses under ICU. Pseudo-locale screenshots show no clipped text at 1280x720. Swedish number formats are checked (for example `12 345,6`).
- UX-T38 *Names.* The generator is deterministic for the same inputs. 1M generated names produce zero blocklist hits, zero exact real-genus hits and no names longer than 24 characters, with at least 99.9% unique within a world. A daughter species inherits the genus below the genus threshold.
- UX-T39 *Rename.* Rename events propagate to all views and the phylogeny, and appear in a captured `.ptk` file.
